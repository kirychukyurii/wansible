## Стиль конфігурації юнітів (v26.04, зведено)

Усі юніти: `Type=simple`, `User=webitel`, `EnvironmentFile=/etc/default/webitel-<name>`
(required) + опційні `-/etc/default/webitel-otel` та `-/etc/default/webitel`. Файл(и)
постачає пакет. Ansible конфігурує редагуванням env-файла на місці (`lineinfile` по
ключах), без ExecStart drop-in і без власних шаблонів.

| Сервіс | Юніт(и) | env-файл(и) пакета |
|---|---|---|
| core | webitel-{api,app,uac,portal} | **per-unit:** `/etc/default/webitel-{api,app,uac,portal}` (НЕ спільний `/etc/default/webitel`) |
| messages | webitel-messages-{srv,bot} | **per-unit:** `/etc/default/webitel-messages-{srv,bot}` (srv←`.env.app`, bot←`.env.bot`) |
| engine | webitel-engine | `/etc/default/webitel-engine` |
| call_center | webitel-call-center | `/etc/default/webitel-call-center` |
| flow_manager | webitel-flow-manager | `/etc/default/webitel-flow-manager` |
| storage | webitel-storage | `/etc/default/webitel-storage` (юніт: `ProtectSystem=strict`, RW лише `/opt/storage`+`CacheDirectory`) |
| logger | webitel-logger | `/etc/default/webitel-logger` |
| cases | webitel-cases | `/etc/default/webitel-cases` |
| media-exporter | webitel-media-exporter | `/etc/default/webitel-media-exporter` |

## Ключі підключення per-сервіс (інфраструктурні адреси, які ansible перевизначає)

Легенда обчислених значень: `C`=webitel_consul_address, `A`=webitel_amqp_url, `D`=webitel_pg_dsn_base, `OS`=webitel_opensips_host, `PUB`=webitel_public_url, host=`ansible_facts.default_ipv4.address`.

### core — `/etc/default/webitel` (MICRO_/WEBITEL_/WBTL_/OPENSIPS_)
```
MICRO_REGISTRY=consul
MICRO_REGISTRY_ADDRESS=<C, host без :8500>
MICRO_BROKER=rabbitmq
MICRO_BROKER_ADDRESS=<A>/
MICRO_CLIENT_REQUEST_TIMEOUT=50s
WEBITEL_DBO_ADDRESS=<D>?sslmode=disable
OPENSIPS_MI_ADDRESS=http://<OS>:8000/mi
OPENSIPS_SIP_ADDRESS=<sip addr>
WBTL_AUTH_URL=<PUB>/api
WBTL_LOGIN_URL=<PUB>/auth
WBTL_LOGOUT_URL=<PUB>/auth
WBTL_COOKIE_KEYS=<cookie keys>
WBTL_*_TTL=...
```
Перевизначаємо: MICRO_REGISTRY_ADDRESS, MICRO_BROKER_ADDRESS, WEBITEL_DBO_ADDRESS, OPENSIPS_MI_ADDRESS, OPENSIPS_SIP_ADDRESS, WBTL_AUTH/LOGIN/LOGOUT_URL, WBTL_COOKIE_KEYS.

### engine — `/etc/default/engine`
```
ID=1

```
Перевизначаємо: CONSUL, AMQP, DATA_SOURCE, OPEN_SIP_ADDR, SIP_PROXY_ADDR, GRPC_ADDR, PUBLIC_HOST (WS_SIP_ADDR — [VM]).

## Listen/bind-адреси (на якому інтерфейсі слухає сервіс)

`GRPC_ADDR` (основний gRPC bind/advertise) — перевизначається на host IP у ВСІХ Go-сервісах (127.0.0.1 single / приватний IP multi). Додатково перевизначаються вторинні listen-адреси, що дефолтяться на localhost:

| Сервіс | listen-ключ | Значення | Стан |
|---|---|---|---|
| engine | `GRPC_ADDR` | host IP | ✅ |
| engine | `WEBSOCKET` | `:80` (всі інтерфейси) | пакетний дефолт ок |
| engine | `WS_SIP_ADDR` | публічний SIP/WS advertise | [VM] |
| flow_manager | `GRPC_ADDR`, `WEB_ADDR` | host IP (`:5689`) | ✅ |
| storage | `GRPC_ADDR` | host IP | ✅ |
| storage | `PUBLIC_ADDRESS` `:10023`, `INTERNAL_ADDRESS` `:10021` | (закоментовані в example) | [VM] — звірити чи дефолт `:port` (всі інтерфейси); якщо localhost — додати |
| logger, call_center, cases, media-exporter | `GRPC_ADDR` | host IP | ✅ |
| messages | srv `MICRO_SERVICE_ADDRESS` (`host:10039`), bot `WEBITEL_BOT_ADDRESS` (`host:10040`), bot `MICRO_SERVICE_ADDRESS` (`host:10048`) | host IP | ✅ |
| **core api/app/uac/portal** | `MICRO_SERVICE_ADDRESS` (у env, v26.04) → `host:1004{4,5,6,7}` | host IP | ✅ розвʼязано |

Бінд-стратегія: host IP + фіксований порт (пінований блок 10030–10048, по одному на
юніт), consul-advertised. `MICRO_API_ADDRESS` api (HTTP-gateway, :8080) — теж host IP
(`{{ webitel_core_bind_host }}:8080`); ключ закоментований в example, тож задаємо явно.

## Відкриті [VM]-пункти

- ~~Шляхи env-файлів~~ — **розвʼязано:** підтверджено `/etc/default/webitel-<name>` для всіх (з `package-contents` v26.04). core/messages — per-unit (див. таблицю вгорі).
- ~~messages: один env-файл чи два~~ — **розвʼязано: два** (srv←`.env.app`, bot←`.env.bot`).
- ~~core api/app listen-адреса~~ — **розвʼязано:** `MICRO_SERVICE_ADDRESS` тепер у env → host IP + фіксований порт (10044–10047 core, 10048 messages-bot).
- engine `WS_SIP_ADDR`, flow_manager `ESL_HOST`/`REDIS_*`, media-exporter `REDIS_ADDR`/`DATA_SOURCE` — значення залежать від фактичної розкладки; перевизначаємо лише за потреби multihost.
- ~~`MICRO_API_ADDRESS` (api HTTP-gateway)~~ — **розвʼязано:** задаємо явно `{{ webitel_core_bind_host }}:8080` (закоментований у example), single→`127.0.0.1:8080`, multihost→`hostIP:8080` для nginx-consul.
- portal: не стартуємо (потрібна окрема схема в БД); env сконфігуровано, юніт не в `units`.
- Облікові дані: .env.example використовує `admin:admin`@rabbit / `postgres:postgres` — у нас rabbitmq-юзер `webitel`, pg-юзер `opensips`; значення беруться з наших обчислених DSN/AMQP, не з прикладу.
